2026年10月工作日报 📌

这里按天记录工作内容、遇到的问题和当天的一点想法，方便月底回看。

2026/10/07 今天做了啥？ ✨

今天主要是在把 4 个重点事项往真实链路、明确口径和可落地结论上收，既有问题排查，也有流程和记录方式上的整理。

✅ 工作内容

  • 完成熙牛医疗资料包整理与复核，围绕截图中的六条经历形成简历写法、核心实现与面试追问、高频问答三部分；其中核心实现覆盖 18 个追问，高频问答整理了 24 题，并已检查相对链接、代码围栏与表述一致性。
  • 定位并修正医疗搜索章节的错贴内容，确认 医疗/熙牛产出.md 原流程是景区推荐链路，与医疗搜索无关；已替换为“数据同步 → Elasticsearch 患者索引 → 患者检索 → 游标分页”的业务流程，并补齐空结果分支。
  • 对齐患者检索的分页与字段检索边界：首次查询携带查询条件、排序和 size、不带 search_after；后续页面使用上一页末条的完整排序值继续查询。姓名等字段按实际分词策略匹配，病历号、身份证号等按业务需要走精确或前缀匹配，不把分词等同于任意子串模糊检索。
  • 复核资料中的事实边界，明确 afterCommit 只表示事务已提交，不能推导为连接已归还或任务自动异步；“2.5 秒到 800ms”等截图指标只保留为可选量化表述，故障数、SLA 和具体同步组件均不作为已验证事实。

🧩 困难/需要帮助

  • 熙牛医疗材料中的性能指标、实际同步组件（Canal 或 Logstash）和部分机制仍缺源码或运行数据佐证，后续需要结合真实实现继续核实，避免把建议方案写成已落地能力。
  • 暂无其他明确外部阻塞。

💭 感想

今天主要是在把医疗搜索和简历材料从错贴、泛化描述往真实检索链路和证据边界上收敛。技术方向已经清晰，后续重点是补足源码与运行数据，让项目表述既具体又经得起追问。

2026/10/08 今天做了啥？ ✨

今天主要是在把 7 个重点事项往真实链路、明确口径和可落地结论上收，既有问题排查，也有流程和记录方式上的整理。

✅ 工作内容

  • 完成 WeKnora 商家资料生题隔离链路合并，CP、Backend 接入 tenantId → Portal 工作空间 → 知识库，只允许所选且解析完成的资料进入生题，冻结 Manifest 并在执行、恢复、落题前复核，跨商家、旧空间和过期资料会阻断；Knowledge 定向 144 项、CP 定向 139 项及前端构建通过。
  • 收口 CP—Knowledge 的 weknora_v1 契约，支持首次建任务、按租户和模式查询最新任务、结果分页及原审核入口；修复最近任务查询漏传 generationMode=weknora_v1，API 定向用例 3 项通过，并补回 Bad Case 驳回必须填写原因的规则。
  • 梳理 QA-SC 正式生题的库表升级边界，确认 sellai_train.ai_qb_formal_gen_task 的 V54 仍待落地；现有建表工具会静默丢失生成列定义，不能直接用于本次变更，已明确要走保留旧列、索引和生成列的安全执行路径。
  • 定位商家 189891 的资料导入失败根因，material 15870/task 7991 卡在 Portal 节点落库时 sort_order 为 NULL；同时确认删除动作已取消排队任务并向执行任务发出取消信号，但索引是否彻底清理仍缺少闭环证据。
  • 完成 CP 后台员工新增/编辑输入白屏修复，根因是 React 事件回收后延迟读取 event.target.value；姓名和手机号改为即时取值，逐字输入、粘贴、删除等 16 项回归及前端构建通过，已提交 3b4e263。
  • 完成席位批次“未启用/启用/暂停恢复”最小实现并在 QA-SC 验收，复用原状态与生效/过期时间，不新增 DDL；未启用批次不计时不分配，首次启用通过 CAS 和行锁启动，验收批次的日期与剩余天数展示符合预期。
  • 完成商家后台题目反馈页面隐藏的代码审查和发版预检：菜单及前后端精确路由已隐藏，旧链接进入 404、题库管理保留；提交 682bd16、MR !32、9 项测试、前后端构建和生产发布预检均通过，生产合并与发布结果待单独确认。

🧩 困难/需要帮助

  • V54 库表升级不能直接使用当前生成列会被吞掉的建表工具，需要先确认可信的执行路径，再做 QA 库变更。
  • 资料删除的任务取消证据已齐，但索引清理尚未证实；sort_order=NULL 的 Portal 落库修复和导入回归也需要继续跟进。
  • 生题隔离的定向测试和构建已通过，但 QA-SC 仍需按真实商家、资料解析和落题结果补齐端到端验收，不能把代码合入当作业务闭环。

💭 感想

今天主要是在把“商家资料→解析→生题→落题”从页面和接口层往真实的 Portal、任务、库表和版本口径上收。隔离方向已经比较明确，后面要把数据迁移、Portal 修复和环境验收拆开核对，避免用局部通过替代完整交付。

2026/10/09 今天做了啥？ ✨

今天主要是在把 6 个重点事项往真实链路、明确口径和可落地结论上收，既有问题排查，也有流程和记录方式上的整理。

✅ 工作内容

  • 完成商家知识资料链路回查，确认 doc2 / material 15930 / task 8040 与 doc3 / material 15931 / task 8041 均已完成解析并进入 stable、succeeded；第三份转换版资料已创建平台知识记录，具体终态仍待补充核验。
  • 完成商家知识聊天页交互改造与本地验收，折叠导航、资料抽屉、中文输入法 Enter 保护和紫色按钮已统一；本地构建及 73 项检查通过，桌面和窄屏表现已确认。
  • 定位 QA 实际问答未通的直接原因：WeKnora builtin-quick-answer 缺少 model_id；同时确认“商家知识请求未完成”对应 Node 未映射或无业务码异常，不能直接按超时处理。
  • 确认小程序分发失败根因：商家 190188 的门店 277250 在 14:57 停用，15:42 的三次分发均返回 STORE_DISABLED，且在扣减席位前被拒绝；小程序仍可选择停用门店，并吞掉了具体错误。
  • 查清停用门店席位异常：原 14 个席位回收总部后旧记录未清，后续转入 3 个席位时旧记录被复活为 17 个，转回后遗留 14 个。已对齐查询/提交仅允许 enabled 门店、共用分配逻辑阻止 closed 记录复活的最小防复发范围。
  • 完成生产数据修复前置核验，目标记录已严格收敛到 id=200 / tenant=190188 / store=277250 / batch=76671；但 16:10 回查仍为 allocated=14 / used=0 / active，生产修复尚未生效。

🧩 困难/需要帮助

  • 聊天页目前只完成本地验收，QA 问答还需补齐 WeKnora 智能体的 model_id；页面“解析完成”不等于真实问答链路已通过。
  • 门店当前只有停用、没有删除接口；生产席位修复需要等待 DML 工单 4802227 的审批/执行结果，并对目标记录和总部席位汇总做读回确认。
  • Java 9fe2c26 仅完成静态预检，隔离构建、推送和 QA provider 核验尚未执行，不能按已发布处理。

💭 感想

今天主要是在把“页面改好了、资料解析完成、真实问答可用”这几个状态拆开确认，避免把局部验收写成端到端闭环。

小程序分发和席位异常已经收敛到具体门店、状态契约和残留记录，下一步要盯住生产数据修复的读回，以及前后端对停用门店的共同约束。
